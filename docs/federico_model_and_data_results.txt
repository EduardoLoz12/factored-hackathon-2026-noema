1. EXECUTIVE RESULT

The local data, capacity-model, and Semantic Cognition Matrix work is complete.
The full pipeline processed all 13 source tables and 23,495,188 rows. The dbt
build completed 20 models and 5 data tests with no errors. The repository test
suite passed with SCM both enabled and disabled.

The capacity model is deliberately conservative. It estimates a sustainable
monthly payment from observed approved transactions and abstains when history
is insufficient or ambiguous. It is a cash-flow proxy, not an observed label
of customer solvency and not an approval decision.

  For example, 268,028 null credit limits are structural, while 6,655 are
  missing on products where the field should apply.

Referential integrity
- Found 149,995 customers with an invalid optional registration-branch link.
- Found 831 service agents with an invalid optional assigned-branch link.
- Preserved all 150,826 original rows and rejection reasons in a reference
  quarantine, while clearing only the invalid optional relationship in silver.
- Found zero orphan customer/product references in products and transactions.

Duplicate and row preservation controls
- Verified zero excess primary-key duplicates across all 13 full tables.
- Verified every contract-stage input row is either validated or quarantined;
  no rows disappear silently.
- Kept all 23,495,188 source rows accounted for at the contract stage.

Enumerations and redundant fields
- Normalized product types into one Spanish vocabulary.
- Normalized transaction types from English to a consistent Spanish vocabulary.
- Removed redundant contact_reason from the call-center silver table because it
  duplicates reason_category.

Currency handling
- Recomputed transaction USD values with the exchange rate from the operation
  date, rather than trusting an undocumented value or using a future rate.
- Quarantined 607 transactions that lacked an exact-date FX rate.
- Valued all customer products in customer_360; zero products remained without
  a USD valuation at the selected valuation date.

Temporal leakage prevention
- Created 141,445 customer feature rows with an explicit 2025-12-31 cutoff.
- Required both transaction_date and process_date to precede the cutoff, which
  excludes late-arriving records that were not available at decision time.
- Confirmed the latest included event and process dates are 2025-12-30.
- Excluded current_balance, last_transaction_date, product_status,
  days_past_due, and all post-cutoff aggregates from model features.

Measured data-quality findings retained for analytics
- 72,548 customer phone-country mismatches were reported, not auto-corrected.
- 1,106,307 transactions have operation dates different from process dates.
- 200,398 products belonging to Mexican customers are denominated in a
  non-MXN currency; the inconsistency is reported rather than fabricated away.
- 30,033 customers lack estimated monthly income, confirming why the capacity
  model uses observed transaction flow instead of declared income.

5. CURRENT LIMITATIONS AND NEXT INTEGRATIONS

- The model's gain over baseline is small and should be described honestly.
- Capacity is a proxy built from cash flow, not observed repayment capacity.
- The model abstains frequently by design; broader useful coverage requires
  better direction labels for transfers and more consistent monthly history.
- Eduardo must connect predict_capacity and the SCM to the shared predictor and
  orchestrator.
- Databricks and Postgres implementations are ready in plan mode but still need
  execution and read-back verification against real configured destinations.
- A versioned credit policy is required before product_policy can become ready.
